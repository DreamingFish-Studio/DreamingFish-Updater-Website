完整部署教程

同时覆盖 Web 管理路径与可交互终端路径，从全新管理端开始，一直完成玩家实例接入、下载服务验证和首次启动测试。

Windows / Linux 管理端Web + 交互终端PCL 示例首次部署与日常发布
i
先理解整体关系

管理端负责制作和发布；玩家端随整合包分发，并在 Minecraft 启动前运行。玩家端不是启动器，玩家依然从原有启动器点击“启动游戏”。

一、准备发行包与三个位置#

管理端和玩家端发行包都自带运行环境，不需要额外安装 Java。建议先准备以下三个固定位置：

Windows 目录示例
D:\DFSAdmin       管理端程序与自动生成的数据
D:\DFSSource      服主希望更新器管理的内容
D:\MyModpack      准备发给玩家的完整 Minecraft 实例
  • D:\DFSAdmin 应长期保留，升级管理端时继续使用其中的 data 和设置文件。
  • D:\DFSSource 不要求是完整游戏目录。只管理模组时可以只有 mods；只管理配置时也可以只有需要的 config。
  • D:\MyModpack 是最终交给玩家的完整实例，它由启动器、游戏文件和 DreamingFish 组件共同组成。

二、选择管理入口：Web 或交互终端#

日常推荐

Web 管理界面

适合创建项目、上传或导入源文件、查看扫描预览、发布版本、回滚、发布玩家端程序和生成首次部署包。

  • 在主菜单选择 [10] 启动 Web 管理界面
  • 管理端本机访问 http://127.0.0.1:18080/
  • 远程服务器通过 SSH 隧道访问，不应公开 18080
服务器友好

可交互终端

中文菜单提供完整的项目、扫描、发布、实例和服务操作，不依赖桌面环境。加密备份与恢复等高风险能力只在终端中提供。

  • 首次启动可直接完成基础配置与首个项目创建
  • 服务运行时按 Ctrl+C 返回主菜单
  • 适合 Linux VPS、远程桌面不稳定或纯命令行环境

三、安装并首次启动管理端#

解压到固定目录

Windows 将管理端压缩包解压到 D:\DFSAdmin，Linux 解压到长期使用的目录。不要每次升级都新建一套空目录。

运行管理端

Windows 双击 DreamingFishAdmin.exe 或从 PowerShell 启动；Linux 使用发行包中的启动程序。

完成首次配置

HTTP 监听地址通常直接使用 0.0.0.0，端口通常使用 8080。管理数据会自动创建在管理端根目录的 data 中。

!
两个端口用途不同

8080 是玩家下载发布内容的公共端口；18080 是服主本机使用的 Web 管理端口。不要把管理页面直接暴露到公网。

四、打开 Web 管理界面或留在终端#

管理端就在当前电脑#

在交互主菜单选择 [10] 启动 Web 管理界面，然后打开：

本机 Web 地址
http://127.0.0.1:18080/

管理端位于远程服务器#

在自己的电脑建立 SSH 隧道，保持终端窗口运行，然后仍然访问本机的 127.0.0.1:18080：

SSH 隧道
ssh -N -L 18080:127.0.0.1:18080 用户名@您的服务器地址

SSH 使用非默认端口时增加 -p SSH端口。隧道只把你电脑上的端口转到服务器回环地址，不会让管理页面面向公网开放。

只使用交互终端#

可以不启动 Web 页面，直接在主菜单中依次完成项目配置、扫描、发布、玩家程序、实例制作和公共服务控制。Web 与终端使用同一份管理数据，因此两种入口可以按需切换。

五、创建整合包项目#

首次运行可以在终端提示中创建，也可以稍后从 Web 首页点击“新建项目”。建议先填写以下内容：

字段示例用途
项目 IDdreamhaven项目固定标识，只使用小写字母、数字、点、下划线或连字符。
显示名称梦屿玩家端展示的项目名称。
标准整合包目录D:\DFSSource服主维护的目标内容来源。
公共 HTTP 地址http://公网IP:8080玩家电脑实际访问的下载地址，不能填写 127.0.0.1、localhost 或 0.0.0.0。
强制同步目录首次留空第一次部署建议先使用默认同步，确认流程稳定后再按需启用。
服务器地址、封面与颜色按项目填写用于玩家端的服务器信息与品牌展示。

六、准备标准整合包内容#

把希望由更新器管理的文件放进标准目录。例如：

标准目录示例
D:\DFSSource\
  mods\
    mod-a.jar
    mod-b.jar
  config\
    mod-a.toml
    mod-b\settings.json
  resourcepacks\
    server-assets.zip

Web 页面可以从浏览器上传多个文件，也可以导入管理服务器本机文件；交互终端路径下也可以直接使用系统文件管理工具维护标准目录，然后回到管理端扫描。

七、发布玩家端程序#

玩家端程序版本与整合包发布版本是两条独立的版本线。第一次部署时需要先发布玩家端程序；以后只更新模组或配置时不需要重复发布。

  1. 把玩家端发行包解压到一个临时目录。
  2. Web 进入“玩家端程序”，或在终端进入对应菜单。
  3. 选择平台，例如 windows-x64，并指定解压后的发行包根目录。
  4. 管理端读取玩家端版本并保存签名程序清单。
  5. 发布完成后，临时解压目录可以删除。
i
什么时候再次发布玩家端程序？

只有更新器应用本身发布了新版本，并希望玩家自动升级时才需要。新增模组、修改配置或发布整合包版本都不等于发布玩家端程序。

八、扫描并发布第一个整合包版本#

扫描标准目录

管理端读取当前目录，生成新增、修改、移除和同步策略预览。

确认变化

检查路径与文件数量。发现错误时先修改标准目录并重新扫描，不要带着错误直接发布。

填写版本信息

填写面向玩家的显示版本、最低玩家端程序版本与更新记录。

发布

发布后形成不可变版本。需要修正时继续发布新版本，而不是直接改写旧版本。

如果扫描中出现“移除”，必须为每个已发布文件选择：

  • 删除玩家文件：玩家更新时移除旧托管文件；普通模式下已有玩家本地豁免仍然优先。
  • 放弃管理并保留：文件不再由项目管理，但玩家电脑上的现有副本继续保留。

九、准备玩家实例#

管理端无法访问完整实例

在 Web“玩家实例”页生成薄首次部署包，或在终端生成部署目录。它只包含玩家端、Agent、项目绑定、封面和签名基线。下载后把全部内容合并到 D:\MyModpack。

管理端可以直接访问完整实例

直接制作玩家实例，让管理端写入项目绑定、补齐所选发布文件、保存基线并带入项目封面。

!
隐藏目录不能遗漏

合并薄部署包时必须保留 .dreamingfish-bootstrap。只复制可见文件会导致启动前检查无法运行。

十、接入现有 Minecraft 启动器#

以 PCL 的版本隔离实例为例，在这个具体 Minecraft 版本的 JVM 参数中加入：

PCL / JVM 参数
-javaagent:"{verpath}.dreamingfish-bootstrap/bootstrap-agent.jar"

必须保留 {verpath}。不要改成服主电脑的绝对路径，否则整合包分发到其他电脑后会失效。导出整合包时也要确认版本设置被一起带出。

十一、启动公共下载服务并验证#

Web 首页可直接启动下载服务；只使用终端时，在主菜单选择 [9] 启动 HTTP 文件服务。服务运行期间管理端进程需要保持运行。

本机健康检查
http://127.0.0.1:8080/healthz

正常应返回：

响应
{"status":"ok"}

然后从另一台电脑访问项目公共地址对应的健康检查，确认云安全组、防火墙、端口映射和域名都正确。

十二、进行第一次完整启动测试#

  1. 使用 PCL 启动 D:\MyModpack 中的目标版本。
  2. 确认 DreamingFish 玩家端窗口出现，并显示正确的项目名称和封面。
  3. 确认可以获取发布、完成文件检查，并显示更新状态。
  4. 确认 Minecraft 获得启动许可后继续加载，而不需要玩家再次点击启动。
  5. 打开更新记录、运行记录和本地文件页面，确认内容正常。
  6. 测试通过后，再把完整实例导出给普通玩家。

十三、以后如何更新模组或配置#

修改标准目录替换、增加或移除要发布的文件。
重新扫描检查变化与同步策略。
发布新版本填写版本和更新记录。
玩家下次启动自动获取缺少或变化的内容。

日常更新不需要重新制作所有玩家实例，也不需要反复发布玩家端程序。只有准备上传新的“完整整合包下载文件”时，才需要重新生成部署包并绑定该完整包实际对应的发布基线。

十四、升级管理端#

  1. 停止 Web 和公共下载服务，退出旧管理端。
  2. 备份管理端根目录中的 data 和设置文件；重要环境建议使用管理端提供的加密备份。
  3. 用新发行包中的程序文件覆盖旧目录，保留原管理数据。
  4. 重新启动后检查项目、历史发布和文件服务。
!
不要把空 data 当成备份

data 保存项目身份、历史发布和内容对象，也绝不能发给玩家。升级或迁移前先确认备份中确实包含现有管理数据。
