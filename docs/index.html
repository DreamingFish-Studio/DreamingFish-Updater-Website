DreamingFish Updater/概览

概览

从产品角色、工作流程和文档结构开始，快速建立对 DreamingFish Updater 的完整认识。

服主

管理端负责内容与发布

维护标准整合包目录，在 Web 或交互终端中确认变化、发布版本、准备玩家实例并控制下载服务。

玩家

玩家端负责启动前更新

玩家仍使用 PCL、HMCL 或其他现有启动器。DreamingFish Updater 在游戏启动前出现，完成检查后交还启动流程。

一条完整的工作链路#

维护内容服主把需要下发的模组、配置或资源放入标准目录。
扫描发布管理端生成变化预览，确认后形成新的不可变发布。
启动检查玩家从现有启动器进入游戏，玩家端自动运行。
更新并放行差异更新完成后，Minecraft 获得启动许可继续运行。

这套系统的三个原则#

  • 不替代启动器：不接管账号、游戏安装或实例选择。
  • 不把玩家本地内容一概视为错误：默认同步保留额外文件，并提供本地豁免与模组启停。
  • 不让失败留下半套更新：安装过程以事务方式执行，中断时优先恢复原状态。

推荐阅读顺序#

先完成部署

阅读“完整部署教程”，从管理端安装一直完成到玩家首次启动验证。

再理解两端功能

分别阅读管理端与玩家端页面，明确各自负责什么，以及 Web 与终端如何配合。

最后决定同步边界

根据项目实际情况设置默认同步、强制同步和玩家本地管理规则。
