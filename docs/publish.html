扫描、发布与版本

从标准目录的文件变化出发，理解扫描预览、移除处理、不可变发布、玩家端程序版本与回滚。

先扫描，再发布#

扫描会比较标准整合包目录与当前发布状态，生成等待确认的变化预览。预览本身还没有公开，也不会影响玩家。

  • 新增：新进入管理范围的文件。
  • 修改：路径相同但内容发生变化的文件。
  • 移除：以前由项目管理、现在不再存在于标准目录中的文件。
  • 策略变化：强制同步目录或单文件规则发生变化。

移除文件时的两种选择#

删除玩家文件

新发布会声明该托管文件应被移除。默认同步下，玩家已经设置的本地豁免仍然优先；强制文件或强制目录则按服主策略处理。

放弃管理并保留

把后续所有权交还玩家。文件从远程管理范围退出，但玩家已有副本继续保留，后续发布也不再覆盖或删除。

发布是完整目标状态#

每个发布描述当前版本应该由系统管理的全部目标内容，而不是只能从上一个版本应用的一次性补丁。因此旧完整包只要绑定了正确基线，也可以直接更新到当前最新发布。

i
旧发布不可修改

发现错误时应修正标准目录并发布新版本。不要直接改写已经公开的历史记录，否则玩家无法得到稳定一致的目标状态。

三条独立版本线#

版本代表什么什么时候增加
整合包显示版本模组、配置和资源等项目内容每次内容发布
玩家端程序版本玩家看到的更新器应用更新器功能或界面升级
Bootstrap Agent 版本启动前等待许可的引导组件引导协议或兼容能力变化

日常发布流程#

修改标准目录替换或新增内容。
扫描预览核对路径与文件数量。
填写记录说明玩家能感知的变化。
发布玩家下次启动自动跟进。

回滚如何工作#

回滚不是删除当前版本，也不是改写历史。管理端读取某个历史发布的目标状态，并在发布线末端创建一个新的发布。这样所有玩家仍然沿着单一、可追踪的发布线前进。
