常见问题

配置时最容易碰到的几个问题都在这里。先看是不是端口、路径或包选错了，再去改设置，通常会省不少时间。

管理端在 VPS 上，怎么打开 Web 页面？#

在服务器启动 Web 管理界面，再从自己的电脑建立 SSH 隧道：

SSH 隧道
ssh -N -L 18080:127.0.0.1:18080 用户名@您的服务器地址

保持终端运行，在自己电脑打开 http://127.0.0.1:18080/。本机端口被占用时，可以把命令第一个 18080 改成空闲端口，浏览器也跟着改。

玩家自己加的模组会被删吗？#

普通同步默认保留额外模组。整个 mods 被设为强制同步目录时，额外内容会先备份再移出。还有一种例外：匹配已经发布的持续删除或问题版本要求，即使是后来手动添加的，也会处理。强制单个文件不会顺带清理同目录所有模组。

玩家已经豁免了，服主删除后还会处理吗？#

选择“移除玩家副本”并发布后，会。豁免只表示平时由玩家自己维护，不表示有问题的文件可以绕过明确的移除要求。想允许保留，服主应选择“停止维护，留给玩家”。

首次提供和普通同步，怎么区分？#

普通同步会跟随服主更新，缺了会补齐；首次提供只给一份，已有就保留，之后不覆盖，也不会把玩家删掉的文件反复补回。想默认给一份画质、按键配置，之后让玩家自己改，就选首次提供。

跳过几个版本，或者拿旧整合包加入，会漏删文件吗？#

不会靠“有没有经过某个中间版本”来判断。最新发布带着持续要求，只要包里的项目绑定和签名基线正确，旧完整包也会按最新目标处理。还没有联网取到的新要求，离线时当然不知道。

标准目录必须是完整游戏吗？#

不需要。只放你准备管理的文件就行，比如 mods、config、resourcepacks。存档、日志、账号和管理端 data 都不要混进去。

能直接上传 ZIP 吗？#

“玩家端程序”支持直接上传通用玩家端发行 ZIP，会检查程序版本和平台。“管理内容”的添加文件用于逐个文件或文件夹，不会把任意整合包 ZIP 自动解压成模组目录。两处上传用途不同，别把整合包 ZIP 当成更新器发行包。

网页和终端做的事情一样吗？#

项目、规则、扫描、签名和发布使用同一套服务。网页有上传清单、暂存检查、逐项重试、导入记录、个性化实时预览和发行 ZIP 检查；交互菜单更适合服务器上已经整理好的文件，维护规则等高级功能有参数命令。加密备份和恢复目前在终端提供，不能把菜单理解成网页的逐项复制。

浏览器要一直开着吗？#

不用，关浏览器不会停止管理服务器。不过正在用浏览器上传文件时，别把页面关掉；关上传弹窗可以让任务继续，关闭整个标签页就可能中断。玩家下载服务要保持运行；只需要下载服务时，也可以在终端选择 [9] 启动 HTTP 文件服务。

已发布的玩家端程序可以删除吗？#

可以在程序历史里移除记录，但先确认还有有效的程序版本可供玩家更新。当前玩家端、最低兼容要求和旧部署包都可能依赖它，不要为了清理列表把唯一的可用版本删掉。

为什么现在都是 0.2.0，整合包却填 1.0.0？#

0.2.0 是这次更新器程序的发行版本，管理端与玩家端统一使用。整合包显示版本由服主填写，只用来描述自己的内容发布；Bootstrap Agent 仍是 0.1.2。它们不需要跟着每次模组更新一起改。
