安全、离线与事务恢复

从可信发布、对象传输到本地安装，了解 DreamingFish Updater 如何验证内容，并在更新中断时恢复玩家实例。

安全模型：传输成功不等于内容可信#

玩家端不会因为服务器返回了文件就直接安装。系统先验证发布清单的身份与结构，再按清单逐个验证内容对象，最后在事务中写入实例并重新校验目标状态。

发布身份

每个整合包项目拥有独立的 Ed25519 签名身份。管理端保管私钥，玩家实例绑定项目公钥。

内容身份

每个文件对象由 SHA-256 哈希与声明大小标识。只有完全一致的对象才会进入安装缓存。

签名清单与防重放#

  1. 玩家端从项目绑定中读取项目 ID、公共地址与受信任公钥。
  2. 下载最新发布清单后，先验证响应携带的 Ed25519 签名。
  3. 随后验证清单结构、项目 ID、最低玩家端版本和能力要求。
  4. 清单序号不能低于已经接受的最高序号；同一序号的发布 ID 或清单哈希不能被替换。
✓
公共文件服务不能自行伪造可信版本

即使下载地址或网络链路返回了另一份 JSON，只要它没有项目私钥产生的有效签名，玩家端就会拒绝该发布。

文件传输与下载校验#

  • 对象地址以内容 SHA-256 为标识，下载完成后重新计算完整文件哈希。
  • 同时检查实际大小，超过声明大小会立即终止，大小或哈希不一致会报错。
  • 中断分片支持 Range 续传，但服务器必须返回匹配偏移与总大小的 Content-Range。
  • 分片写入完成后先刷新到磁盘，校验通过后再提升为缓存对象。
  • 多个对象可以并行下载，但每个对象独立完成大小与 SHA-256 校验。
i
HTTP 与 HTTPS 的边界

签名和哈希在应用层保证发布真实性与内容完整性，因此被篡改或截断的内容不会安装。公网部署仍建议使用 HTTPS，以保护访问地址、请求元数据和网络隐私。

路径与实例边界#

发布路径必须是规范化的相对路径。系统拒绝绝对路径、空段、.、..、反斜杠、Windows 禁止字符与设备名、大小写路径碰撞，以及通过符号链接逃离实例目录的情况。

原子安装事务#

安装前，系统为本轮可能修改的文件和可信元数据创建备份，并写入带阶段的事务日志：

BACKED_UP

备份完成

旧文件、清单、签名、可信状态和安装元数据已经保存。

COMMITTING

正在提交

安装、删除或归档操作开始写入玩家实例。

VERIFYING

验证目标

重新检查所有应强制一致的文件是否存在、大小与哈希正确。

COMMITTED

完成提交

保存新可信状态，完成玩家文件归档，最后清理事务目录。

单个文件替换也不会直接覆盖目标：内容先写入同目录临时文件、刷新到磁盘，再使用原子移动替换；文件系统不支持原子移动时使用替换移动作为兼容路径。

中断与自动恢复#

每次开始新更新前，玩家端都会先检查未完成事务。事务停留在提交阶段时，系统使用备份恢复原文件和原元数据，再删除未完成事务。如果更新失败时无法恢复，玩家端会明确报出恢复失败并阻止把当前状态视为可信安装。

并发与游戏运行状态#

  • 同一 Minecraft 实例同时只能运行一个更新任务。
  • 游戏正在使用实例时，不会执行新提交，也不会恢复处于提交阶段的旧事务。
  • 下载、安装和校验过程都响应取消请求，取消不会被标记为更新完成。

更新服务暂时不可用#

实例已有可信基线

玩家端重新验证最近一次可信安装；状态完整时可以给出离线启动许可。

实例没有签名基线

可以明确显示“未验证离线启动”，但不会把它描述成已经通过文件验证。

签名无效、旧发布重放、危险路径、哈希不一致和事务损坏不属于普通网络故障，不能借由离线策略绕过。

强制同步产生的玩家归档#

强制目录中的额外玩家文件不会直接永久删除，而是先进入长期归档目录，并生成文件索引。归档完成后才从实例移出；事务失败时，归档操作也会随旧实例一起恢复。
