日常维护

恭喜你完成了配置！平时加文件、换版本、删东西，都可以在这一页找到。遇到“以前留给玩家，后来才发现有问题”的文件，也有地方处理。

日常更新客户端流程#

日常其实就三件事：整理文件、查看改动、发布。文件和设置保存了，不代表已经发给玩家；看看顶部的待发布提示，再去“检查并发布”确认一次就好。

给客户端加文件、换模组版本#

在“管理内容”进入 mods、config 或资源包目录，点“添加文件”。先暂存检查，再确认导入；同一个模组升级时，检查清单会帮你找到旧文件，选择“替换旧模组”就行。上传失败可以单独重试，想撤回刚才的导入就用“导入记录”。

文件本来就在服务器上，也可以直接改标准目录后重新检查。两条路都一样：最后到“检查并发布”，核对变化，写本次显示版本和更新记录，再发布。

从玩家端删除，还是留给玩家？#

把文件从标准目录移出，或者在网页选择移除后，管理端会让你选：

  • 移除玩家副本：这个文件不该继续留在游戏里。发布后，匹配的玩家副本会先备份，再移出；已经豁免、停用或自己管理的副本也会处理。
  • 停止维护，留给玩家：服主不再更新它，但玩家可以继续留着用。服务器不再下发，玩家也可以自己添加。
!
删除要求会一直有效

例如 4.0 有 D，5.0 删除 D：拿着 4.0 完整包、第一次在 5.0 加入的玩家，也会移出 D。玩家在 5.0 又手动装回 D，下次启动仍会处理。以后重新提供这个模组，会结束普通删除要求；历史问题版本的处理则需要明确结束。

只是“不想再管”，选留给玩家；确定它不能继续用，选移除。强制整个文件夹时，里面不能留下额外内容；想交还给玩家，先把文件夹改成普通同步，再检查并发布。

之前留给玩家的文件，后来出问题怎么办？#

比如 1.0 发过 B，2.0 你选了“停止维护，留给玩家”。过了一阵才发现 B 1.0 会让游戏崩溃，这时标准目录里已经没有它，普通删文件也没法再删一次——去历史记录里处理就行。

  1. 打开“管理内容”里的“历史文件与问题处理”，进入“按发布版本管理”。
  2. 选择当时提供 B 的整合包版本，比如 1.0；可以搜索文件名。
  3. 找到 B 1.0，点击“处理这个版本”，选择移出问题版本，写清楚原因并保存。
  4. 回到“检查并发布”，确认问题处理出现在预览里，再发布新版本。

玩家下次在线检查到这个版本后，匹配的 B 1.0 会先备份再移出，豁免、停用或改名也不能绕过。正常的 B 2.0 不会因为 B 1.0 出问题就一起被移除。匹配会检查内容指纹；模组还会检查 ID 和版本，同一个版本号的改包也可能被认作问题版本。

需要换成好的版本时，先上传正确文件，再从“处理问题文件”的替换选项选择相应修复。“每个玩家重置一次”会覆盖玩家内容，确认有必要再用。

i
保存处理，不等于已经通知玩家

问题处理和普通文件删除一样，需要检查并发布后才生效。离线的玩家还不知道你刚发的新版本；已经运行的 Minecraft 也不会被远程卸载模组，要等下一次启动检查。

普通删除记录由系统持续处理，不会全部挤成首页卡片。历史窗口会标明“已移除（自动处理）”；确实想允许玩家保留，可以在这个文件的“移除要求”里结束要求，再发布。强制文件夹仍然按文件夹规则处理。

更新玩家端程序#

更新器程序本身有了新版本，才去“玩家端程序”上传新的发行 ZIP。先检查版本与平台，再确认发布，最低 Agent 版本按发行说明填写。已经解压在服务器上的包，可以继续用高级目录入口。同版本或更低版本不能重复发布。

玩家端程序有独立的签名清单，安装失败会回到上一个已验证的程序版本。整合包要求的最低玩家端版本更高时，玩家会先升级程序，再更新模组和配置。

改标题、配色、公告和页面，在“玩家端个性化”保存就行；封面与音乐等文件资源按页面提示放进项目后检查并发布整合包。别为了改一句公告重新发一次程序。

Bootstrap Agent 升级时，则需要重新分发接入文件。它由启动器加载，不能像玩家端本体一样在线自更新；分发后检查启动器的 Agent 路径仍然正确。

查看发布历史与回滚#

打开“检查并发布”查看发布历史。点击“回滚”，选好目标版本，填新的显示版本和更新记录，确认后会创建一个更高序号的新发布，旧记录保留。

注意：回滚内容不会悄悄取消已经设置的问题版本处理。旧模组仍是坏版本，就不应该因为点了回滚又装回去。回滚前看一遍预览里的移除和问题处理。

终端回滚示例
dfs-admin project rollback my-modpack r000001-20260802-161030-ab12cd34 --version 1.0.2 --changelog "回滚到 1.0.0" --yes

备份与恢复#

data 是管理端的全部家当：项目、发布历史、签名密钥和内容对象都在里面。想做加密备份，可以在终端运行：

创建加密备份
dfs-admin backup create --output D:\备份\dreamingfish.dfb

密码从环境变量 DFS_BACKUP_PASSWORD 读取，未设置时会在终端提示输入并确认。恢复时用：

恢复加密备份
dfs-admin backup restore D:\备份\dreamingfish.dfb --force
!
恢复前看清楚目录

--force 会替换现有管理数据，确认没有需要保留的新数据再执行。管理服务写入时不要只复制一个数据库文件；做完整备份、完整恢复。备份功能目前在终端提供。

升级管理端#

  1. 下载新版管理端，停止旧管理端进程，再更换程序文件。
  2. 保留原来的 data、management-settings.json 和 management-web-auth.json，如果自定义了 data 位置，也保留那个目录。
  3. 启动新版，检查项目、文件目录和下载服务仍然正确。

从旧版升级到 0.2.0 时，旧发布的原始签名记录会保留；历史删除会迁移成持续要求，先看清预览再发布。首次使用新版规则前先发布 0.2.0 玩家端程序。已经发过新版规则的项目，不要再用旧管理端发布。

多项目与外部托管#

一个管理端可以维护多个项目，各自有独立的目录、签名身份、发布和玩家端绑定。操作前看一眼当前项目；不要把另一个项目的部署包合进去。

想把下载内容放到静态站点、WebDAV 或对象存储，可以打开“外部托管”，先选择托管方式，再填写对应设置。玩家访问地址要指向实际托管的地址，导出后从玩家电脑测试一次。外部托管上传时需要的凭据不要放进玩家包里。
