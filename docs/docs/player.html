玩家端功能与接入

说明玩家端在启动前如何工作、提供哪些界面与本地管理能力，以及它与 PCL、HMCL 等现有启动器的关系。

玩家端不是 Minecraft 启动器#

玩家端不处理账号登录、不下载 Minecraft 本体、不创建实例，也不替代 PCL、HMCL 或 Prism Launcher。它由 Bootstrap Agent 在 Minecraft 主程序加载前启动，完成检查后为本次启动发放许可。

一次启动中会发生什么#

启动器开始启动玩家点击原来的“启动游戏”。
玩家端出现读取项目绑定并连接更新服务。
检查与更新验证发布，只获取缺少或变化的内容。
继续启动发放许可，Minecraft 立即继续。

Minecraft 获得许可后不需要等待更新器窗口关闭。正常情况下玩家端会显示启动提示，并在短暂倒计时后自动关闭；玩家主动打开详情时可以继续保留窗口。

玩家端提供的功能#

功能玩家能看到或做到什么
更新状态查看连接、检查、下载、安装与启动许可状态。
更新记录阅读完整历史发布记录，以及本次更新涉及的文件。
运行记录查看当前启动检查的详细日志，便于定位问题。
新闻与项目展示浏览服主提供的新闻、世界观或公告，并使用项目封面与主题色。
本地文件管理为普通托管文件或目录设置本地豁免，之后不再自动覆盖或恢复。
模组启停停用或恢复非强制模组，查看玩家自选模组。
玩家端自更新在服主发布新玩家端程序后自动安装，并在需要时重启更新器。

本地管理只影响当前玩家#

文件豁免、目录豁免和模组启停规则保存在玩家实例本地，不会上传给服主，也不会改变远程发布。强制同步目录和强制同步文件不能被本地设置绕过。

玩家自己添加的模组#

默认同步下，不属于发布清单的玩家自选模组会被保留并在界面中提示。玩家可以在“自选模组”标签中搜索、启用或停用。停用可能造成依赖缺失或无法进入服务器，玩家端会提供风险提示但不会把所有额外模组一概删除。

接入启动器#

玩家实例必须包含 Bootstrap Agent、项目绑定和签名基线，并在该 Minecraft 版本的 JVM 参数中加入：

启动参数
-javaagent:"{verpath}.dreamingfish-bootstrap/bootstrap-agent.jar"
!
由服主预先配置

普通玩家不应该手动制作绑定或填写绝对路径。服主应把已经接入完成并测试通过的完整整合包直接交给玩家。

玩家端程序与整合包分开更新#

整合包更新改变模组和配置；玩家端程序更新改变更新器应用本身。程序更新拥有独立签名清单，安装失败时可回退到上一个已验证版本，不会与普通模组发布混为一谈。
