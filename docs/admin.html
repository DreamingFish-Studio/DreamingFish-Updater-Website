管理端功能

了解管理端在 Web 与可交互终端中提供的完整能力、数据边界、端口用途和适合的操作方式。

管理端负责什么#

管理端是服主制作和发布整合包更新的工具。它不运行 Minecraft 服务端本体，也不替玩家启动游戏。它维护的是项目、目标内容、发布历史、玩家端程序和分发服务。

三个位置与数据边界#

管理端根目录

程序与管理数据

包含程序、设置和自动生成的 data。这里保存项目身份、历史发布和文件对象，只能由服主保管。

标准整合包目录

服主希望发布的目标内容

可以只包含 mods、config 或其他受管理目录，不需要是完整游戏实例。

完整玩家实例是第三个独立位置。不要把完整 Minecraft 实例、标准目录和管理端 data 混在一起，也不要把管理端数据发给玩家。

Web 管理界面#

  • 固定监听 127.0.0.1，默认端口 18080。
  • 写操作依赖当前进程生成的临时会话令牌。
  • 不应该在云安全组、路由器或防火墙中直接开放到公网。
  • 远程使用时通过 SSH 隧道访问。
  • 按 Ctrl+C 停止 Web 服务并返回主菜单，不会直接退出整个管理端。

可交互终端#

终端适合无图形服务器、远程维护和高风险运维。首次运行会引导设置公共 HTTP 监听并可创建首个项目；之后通过中文菜单完成日常操作。

i
两种入口不是两套数据

Web 与终端调用同一应用服务并读写同一管理数据。可以在 Web 完成日常发布，在终端完成备份或长期运行下载服务。

公共文件端口与管理端口#

端口访问者用途是否可公开
8080玩家端读取发布清单与文件内容需要让玩家可访问
18080服主本机 Web 管理界面不应直接公开

多项目与独立身份#

一个管理端可以维护多个整合包项目。每个项目拥有独立显示信息、公共地址、发布历史、文件源和签名身份。不同项目的玩家实例不应混用绑定文件。

备份、迁移与升级#

普通程序覆盖升级时应保留 data 和设置文件。跨机器迁移或重要生产环境应使用管理端提供的加密备份与恢复，而不是只复制一个数据库文件或只导出私钥。
