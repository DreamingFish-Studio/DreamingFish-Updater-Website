版本与更新日志

这次管理端和玩家端统一整理为 0.2.0。下面列的是现在准备给大家用的功能，以及旧项目升级时需要留意的地方。

启动前检查、自动更新、本地管理与备份恢复。

服主使用

文件工作区、维护方式、签名发布与下载服务。

游戏加载前拉起更新器，等待启动许可并处理程序升级。

0.2.0 · 这次主要改了什么#

  • 日常维护收敛成普通同步、强制同步、首次提供。文件退出维护时，明确选择移除副本或留给玩家。
  • 删除要求持续生效，兼顾旧完整包、跳版本更新、豁免、停用以及后来装回的模组。
  • 以前停止维护的坏版本，可以从历史发布里找到并处理，不需要再把文件塞回标准目录。
  • 管理端改为目录浏览、文件详情和按范围批量设置；问题历史按发布版本查询。
  • 文件夹有清晰的层级、展开收起和完整路径提示，文件与文件夹图标统一重绘。
  • 新增操作记录，文件导入、替换、移除和设置修改可以查询并撤销；误改维护规则时，可恢复当前已发布版本的设置。
  • 上传先暂存检查再确认，同 ID 模组替换、逐项重试、暂停和导入恢复都有明确入口。
  • 玩家端程序支持发行 ZIP 检查，部署 ZIP 可以直接下载，个性化设置按分组编辑并预览。
  • 标题、品牌、公告和背景可按自己的服务器配置，通用发行包使用统一的默认界面。

旧项目升级前先看这里#

管理端数据和账户文件继续保留，旧签名发布也保留。先准备 0.2.0 玩家端程序，再发布使用新规则的整合包。首次扫描会迁移历史删除，服主先检查，确定该删的和该保留的都没选错。

程序发行包只包含通用工具，服务器名称、新闻、音乐和下载地址由自己的项目设置。准备发给玩家的完整包仍然要使用管理端生成的项目部署包。

程序版本和整合包内容，还是分开发布#

本次管理端和玩家端都叫 0.2.0，方便识别这次大改；它们各自的发布流程没有合并。更新模组和配置只发整合包，更新玩家端本体才发程序，Bootstrap Agent 升级则重新分发接入文件。
