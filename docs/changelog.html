0.2.1 · 2026 年 10 月 15 日#

这次新增了管理端桌面版和新版网页工作区，并重新设计了玩家端的更新界面。玩家端、管理端和桌面版都是 0.2.1，Bootstrap Agent 仍是 0.1.2；新维护规则要求的最低玩家端还是 0.2.0。用桌面版连接服务器时，服务器上的管理端需要 0.2.1 或更新。

下载 0.2.1 发行包

管理端桌面版（Windows x64）#

  • 新增 Windows 桌面程序，打开后选择本机管理或远程连接。本机管理自带 Java 21、管理核心和 Bootstrap Agent，可以直接打开已有的管理目录，继续使用原来的项目、账户和发布记录。
  • 远程连接支持 HTTPS 管理地址、已经转发到本机的地址，以及系统 OpenSSH 配置；连接记录可以保存、编辑和移除，不保存密码或私钥。
  • 关闭窗口会收进系统托盘，后台任务和本机下载服务继续运行；明确断开或退出时，会清理桌面版启动的本机服务和 SSH 通道。连接意外中断时回到连接页。
  • 使用和外框同色的自绘标题栏，可以拖动、最小化、最大化和返回连接页；Windows 11 上窗口带系统圆角。

新版工作区（桌面版与网页共用）#

  • 界面重新整理为：图标活动栏、可收起的项目栏、圆角内容卡片、按需出现的右侧面板、底部浮动操作栏和状态栏。新版网页和桌面版是同一套前端，读写同一份项目、版本和操作记录。
  • 网页保留新版界面和旧版界面，可以随时切换，浏览器会记住选择。
  • 文件按类型显示彩色图标（文件夹、模组、配置、脚本、压缩包、图片、数据、音频）；新增快捷键 Ctrl 1–5、Ctrl F、Ctrl A、Ctrl I、Delete、Backspace 和方向键，文件支持右键菜单和拖入导入。
  • 导入文件进入导入清单：先上传检查，看清保存路径、大小、覆盖关系和模组识别，再确认导入，完成后可以直接去检查并发布。
  • “改动与版本”集中了待发布改动、发布版本、操作记录和历史问题文件。发布预览把内部规则名称换成中文说明，写清具体文件和前后变化；“下载量”改为真实的“文件大小”。
  • “发放”集中了部署包、玩家端程序和外部托管；“玩家端设计”以真实玩家端实时预览为主，编辑卡片在右侧。
  • 操作记录在内容区顶部、项目栏、文件工具栏和命令菜单都有入口，支持搜索、类型筛选、前后变化、撤销和恢复当前发布设置；无法撤销时会写明原因。
  • 界面字体改为内置的 HarmonyOS Sans SC；可选内容不能重名。

玩家端更新界面#

  • 首页更新卡片重新设计：状态环区分进行中、已完成、出错和离线启动；进度条下方显示“检查 → 下载 → 安装 → 启动”四个阶段，出错时标出停在哪一步。
  • 本次更新摘要用标签列出安装、删除、备份等数量；更新记录、运行记录和本地文件改为卡片底部的图标入口。
  • 出错时只保留错误说明和“打开目录 / 重试 / 仍然启动”，不再混入上一次更新的摘要。
  • 玩家信息卡增加头像；服主填写了 Minecraft 服务器地址时，旁边显示地址，点击就能复制。
  • 启动后的倒计时提示增加进度条和“保持打开”按钮。

旧版网页界面#

  • 概览新增“整理文件 → 检查改动 → 发布给玩家”步骤条，按当前状态标出下一步。
  • 进入“检查并发布”时，尚未检查或检查已过期会自动检查；版本号按上一个版本自动建议。检查后服务器上的文件又被改动、导致发布被拒时，会自动重新检查并用中文说明。
  • 外部托管的分发方式改为三张选项卡片，界面换用新的深浅两套主题。

0.2.0 · 2026 年 10 月 6 日#

本次是相对于上一个正式发布 v0.1.40 的完整更新。上一发行的玩家端为 0.1.40、管理端为 0.1.26；本次两者统一为 0.2.0，Bootstrap Agent 仍为 0.1.2。更新器程序版本与整合包内容版本继续分别管理。

文件退出维护与历史问题处理#

  • 文件移出标准目录后，明确选择 “移除玩家副本” 或 “停止维护，留给玩家”。前者持续处理匹配的副本，后者把内容交还玩家。
  • 删除要求写入每次完整目标，支持跳版本更新、下载旧完整包后首次加入、玩家豁免、停用、改名以及后来手动装回等情况。匹配的副本先备份，再移出游戏。
  • 例如 4.0 有 D、5.0 删除 D：拿着 4.0 完整包在 5.0 首次加入，也会处理 D；5.0 之后手动装回，下次检查仍会处理。
  • 重新提供同一资源并发布，会结束普通删除要求；历史坏版本的处理要求需要明确结束，避免正常回滚或换版时把坏文件装回。
  • “历史文件与问题处理 → 按发布版本管理” 可以查看当时提供的文件。以前已经停止维护、留给玩家的文件，后来发现严重问题，也能从历史发布选中坏版本并要求移出或替换。
  • 问题版本根据内容指纹及模组 ID、版本识别。只处理指定坏版本，正常的新版本不会仅因使用了旧文件名就一并被移出。
  • 普通删除记录由系统持续处理；主界面集中显示需要服主主动处理的问题，不再把全部删除历史堆成卡片。
  • 必要的移除不会被玩家“保留本地变化”绕过。已取得的有效要求也能在离线时处理；尚未取得的新发布需要联网检查后才生效。

玩家端：可选内容、本地管理与恢复#

  • 新增 可选内容：服主可以把光影、美化等内容组成一组，设置默认是否安装；玩家可整组开关，之后保留自己的选择。
  • 本地文件与模组列表说明版本、管理方式、可选组和限制原因；强制内容不能关闭，其余内容可以停用或自行管理。
  • 模组以 modid 识别，自行管理和停用不会因模组改名而丢失。服主接管已有模组时先备份原副本，重复模组会移入备份。
  • 新增 备份与恢复：按更新记录被移走的文件及原因，可恢复文件、打开或整理备份；恢复前会提示它是否仍受当前移除要求限制。
  • 新增主动恢复首次提供默认文件的入口；本次更新详情能列出备份、保留玩家内容、恢复默认和必要修复等结果。
  • 修复模组停用期间被服主放弃管理后，重新启用会丢失副本的问题。
  • 模组移动、偏好和备份索引共同记录事务，失败或中断后可以恢复。一次性修复与初始化状态会保存，避免每次启动都覆盖玩家后来做的修改。
  • 修复更新结束后进度条仍持续滚动、详情抽屉后方内容透出、布局被横向挤偏和界面版本显示滞后的问题。

管理端：文件工作区与上传#

  • 日常操作整理为 “管理内容” 和 “检查并发布”。文件和规则保存后显示待发布状态，服主检查确认后才发给玩家。
  • 文件夹导航支持层级连线、展开收起、完整路径提示及空目录浏览；长名称保持一行，文件夹与文件采用统一重绘的蓝色文件夹和折角纸张图标。
  • 文件区底部、“操作记录”左边新增“返回上一级”。每次退回一层，根目录时禁用，切换目录后重置文件表滚动。
  • 文件列表支持跨目录搜索、筛选、详情与批量操作。隐藏范围内仍有选中项时会计数提示，目录统一设置前会说明影响范围。
  • 上传改为 选择文件或文件夹 → 暂存并检查清单 → 确认导入。清单显示实际保存路径、大小、模组 ID、版本及冲突，选择文件后不会立即覆盖标准目录。
  • 支持保留或去掉所选文件夹的外层名称，内部目录结构会保留，减少 mods/mods/ 等错误位置。
  • 同一 modid 换版本时可以识别旧文件，归档替换并沿用维护方式和可选组；发现设置不一致或同名内容冲突时，会要求先核对。
  • 文件任务支持逐项重试、暂停、后台继续处理、断开后的重新检查和导入记录恢复；完成的文件不会重复写入。

操作记录、撤销与恢复版本设置#

  • 新增项目操作记录，查询设置修改、导入、替换、移除、新建目录和整合包发布，可搜索、筛选并查看具体变化。
  • 可恢复的操作提供 “撤销…”：先预览要恢复的文件与设置，再确认执行。已经撤销的记录继续保留，后续修改会受到保护。
  • “恢复版本设置…” 以当前最新整合包发布为基准，恢复维护方式、可选内容、额外文件处理与问题要求，逐项显示当前值与恢复值。
  • 新发布在管理数据中保存精确维护设置快照，旧签名记录保持不变；没有快照的旧发布按有效签名内容重建可恢复规则，无法等价恢复时提示原因。
  • 恢复维护设置不会替换源文件。恢复源文件用对应操作的撤销，恢复已发给玩家的内容用回滚发布；撤回已经发布的变化后，仍需检查并创建新的发布。

玩家程序发布、个性化与分发#

  • Web 可以直接上传玩家端发行 ZIP，检查程序版本、平台和目录后再签名发布；服务器已有解压目录的入口继续保留。
  • 玩家实例优先提供 下载部署 ZIP，远程管理服务器可以直接把部署包下载到服主电脑；也支持写入服务器目录或在可访问的实例中直接接入。
  • 部署包选择实际对应的整合包发布版本，并携带签名基线；拿旧完整包首次启动时，能正确识别旧托管内容并直接更新到最新发布。
  • 玩家端个性化按标题与品牌、外观、音乐、公告与页面分组编辑，提供真实界面预览；窄窗口可切换编辑与预览。
  • 标题、配色、公告与页面继续在保存后供玩家下次启动获取；封面和音乐按文件资源流程检查并发布。
  • 新增项目更新地址检测；外部托管按静态导出、WebDAV、对象存储分别展示相应表单。

CLI、脚本与 AI agent#

  • 项目、文件、维护规则、可选内容、历史问题、扫描发布、玩家程序、部署包与操作记录都有参数式命令，不必进入交互菜单。
  • 支持 --json 读取结果，明确的 --yes 可完成有确认步骤的非交互操作。签名、路径、预览过期和客户端兼容检查继续执行。
  • 新增 project operations，支持查询、--undo 操作ID 和 --restore-published。撤销与恢复在 --json --yes 下输出一个 JSON 对象，包含 preview 与 result，可直接交给脚本或 agent 解析。
  • CLI 与 Web 使用同一份项目数据，适合通过 SSH 让 agent 在服务器整理文件、读取预览并按服主要求发布。

稳定性、签名与恢复修复#

  • 拒绝更新路径中的 Windows 目录联接与符号链接，写入、恢复和清理前重新验证，防止越过预期目录。
  • 发布预览冻结文件、规则和项目设置；确认时校验预览摘要和当前状态，修改后需要重新检查。
  • 回滚发布继续保留累计的放弃管理路径及必要问题要求，避免旧内容被错误接回。
  • 静态分发提供单文件 .signed 载荷，避免清单与签名在更新期间跨版本混用；导出与上传携带相应签名文件和缓存规则。
  • HTTP 响应体读取支持超时与主动取消，等待下载工作退出后再结束本次更新。
  • 管理备份替换与回退都失败时，保留旧数据和已验证的恢复目录，并提供恢复位置。
  • 文件覆盖与归档恢复会检查后续变化；修复 Windows 上传流尚未关闭时阻止安装失败回退的问题，文件与操作记录写入失败会共同回退。
  • 项目锁支持同线程内嵌套调用，并继续拒绝不同线程或进程同时写入同一项目。

通用发行包、官网与文档#

  • 玩家端默认界面使用通用标题、品牌与背景，清理专属服务器新闻、页面和测试玩家身份；发行包不带实际项目绑定、管理账户、私钥或项目数据库。
  • 统一玩家发行入口，清理旧 JavaFX 界面、相关依赖及多余运行时文件；程序继续自带运行环境。
  • 官网采用新版设计，教程按实际管理端界面更新；保留创建项目的操作演示、目录图和终端示例，维护方式用三张说明卡片呈现。
  • 教程补充上传清单、历史问题处理、操作撤销、恢复设置、目录返回与脚本/AI agent 调用；宣传片使用原创配乐。

升级与兼容#

  1. 管理端升级时保留 data/、management-settings.json、management-web-auth.json 及自己的标准整合包目录，再替换程序文件。
  2. 先发布 0.2.0 玩家端程序，再发布采用新维护规则的整合包；不支持新能力的旧玩家端会先要求升级。
  3. 旧发布的原始签名与旧清单语义保留，升级后先检查历史删除迁移、持续要求和玩家保留的选择。
  4. 程序版本、整合包内容版本分别发布。只改模组和配置时，不必重新发布玩家程序或重新分发完整包。
  5. 已经采用新维护格式的项目，不要再用旧管理端发布；较旧的玩家程序也不能处理新版恢复事务。
